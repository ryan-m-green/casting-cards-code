Casting Cards — v1 vs v2 Campaign, SignalR & Angular Architecture

This document explicitly separates the legacy v1 campaign shell from the new v2 campaign shell, then explains the shared SignalR hub, Angular signals, and the eventing workflows that both shells use.

1. v1 vs v2 Campaign Architecture — The Big Picture

The codebase currently maintains two parallel campaign shells. v1 is the original route-based shell with dedicated feature pages. v2 is a newer, unified shell with radial navigation, viewport panning, and a shared right drawer.

2. SignalR Setup — Shared by v1 and v2

Both shells use the same CampaignHubService singleton. It opens one WebSocket/SSE connection per browser session and joins the campaign group.

Connection bootstrap

// src/app/core/hub/campaign-hub.service.ts
async connect(): Promise<void> {
  this.connection = new signalR.HubConnectionBuilder()
    .withUrl(`${environment.apiUrl}/hubs/campaign`, {
      accessTokenFactory: () => localStorage.getItem('cast_library_token') || '',
      transport: signalR.HttpTransportType.WebSockets
                 | signalR.HttpTransportType.ServerSentEvents
    })
    .withAutomaticReconnect([0, 2000, 5000, 10000, 30000])
    .withServerTimeout(90000)
    .configureLogging(environment.production ?
                      signalR.LogLevel.None : signalR.LogLevel.Trace)
    .build();

  await this.connection.start();
  this._isConnected.set(true);

  // One RxJS Subject per server event
  this.connection.on('SecretCreated', (event) => {
    this.secretCreatedSubject.next(event);
  });
  // ... SecretRevealed, ShopItemAdded, CastTraveled, etc.
}

The shell starts the hub, joins the campaign group, and the service surfaces inbound events as typed RxJS observables.

Event fan-out

Each server hub method is mapped to a private Subject and exposed as a read-only Observable. Components subscribe to react to real-time changes. 

private secretCreatedSubject = new Subject<SecretCreatedEvent | null>();
readonly secretCreated$ = this.secretCreatedSubject.asObservable();

// Consumer
this.campaignHub.secretCreated$.subscribe(event => {
  this.shellSvc.updateCampaign(c => ...);
});

3. Angular Design Patterns

Standalone components

v2 and right-drawer components are Angular standalone components. They declare their own imports and do not depend on an NgModule. 

@Component({
  selector: 'cc-secrets-manager',
  standalone: true,
  imports: [CommonModule, FormsModule],
  templateUrl: './cc-secrets-manager.component.html',
  styleUrl: './cc-secrets-manager.component.scss'
})
export class CcSecretsManagerComponent { ... }

Signals for reactive state

  • input.required<T>() / input<T>() — component inputs.
  • output<T>() — component events (replaces @Output).
  • signal() — local mutable state.
  • computed() — derived read-only state.
readonly secrets  = input.required<CampaignSecret[]>();
readonly editing  = input<boolean>(false);
readonly add      = output<string>();

adding           = signal(false);
newSecretContent = signal('');
currentSecrets   = computed(() => this.secretsState() ?? this.secrets());

v2 sharable component example: cc-secrets-manager

Built to replace duplicated detail-secrets-section markup across v2 detail content components. It receives data through inputs and reports actions through outputs. 

<cc-secrets-manager
  [secrets]="currentSecrets()"
  [context]="'campaign'"
  [isDm]="true"
  [editing]="editing()"
  (reveal)="onRevealSecret($event)"
  (reseal)="onResealSecret($event)"
  (add)="onAddSecret($event)"
  (delete)="onDeleteSecret($event)" />

4. v2 SignalR Eventing Path

This diagram follows one server-side event from the backend hub all the way to the v2 component that consumes it. It does not include HTTP write paths or parent/child binding; it is purely the real-time notification pipeline.

sequenceDiagram participant Server as "ASP.NET Core CampaignHub" participant Conn as "SignalR connection (one per browser)" participant HubSvc as "CampaignHubService" participant Subj as "RxJS Subject (e.g. secretCreated$)" participant V2Shell as "V2CampaignShellComponent" participant V2Svc as "V2CampaignShellService" participant V2Comp as "v2 component (cc-secrets-manager)" Server->>Conn: Send "SecretCreated" to campaign group Conn->>HubSvc: connection.on('SecretCreated', event) HubSvc->>Subj: subject.next(event) Subj->>V2Shell: this.hub.secretCreated$.subscribe(...) V2Shell->>V2Svc: updateCampaign(c => ...) V2Svc->>V2Comp: campaign signal changes → computed input updates V2Comp->>V2Comp: Re-render with new secret

A single real-time event flows from the server connection into a typed RxJS stream, reaches the v2 shell, updates the shared campaign signal, and finally re-renders the affected v2 component.
